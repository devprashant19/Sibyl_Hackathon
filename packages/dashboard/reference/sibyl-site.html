What we cover

Nothing paged you. It still happened.

No exception. No alert. Sibyl exists for the failures your monitoring was never built to catch.

Silent success

Returns 200 with the wrong body. The trace is green. The value that mattered was never logged anywhere.

Race conditions

Needs two operations to land at the exact same millisecond. Your test suite runs them one at a time, so it never sees it.

Contract drift

A vendor adds a new status value or field. Your parser has no case for it, and quietly does the wrong thing.

Non-idempotent retries

A retry after a timeout processes the same payment twice — or writes nothing at all, because the first attempt half-succeeded.

Partial failures

Step three of four fails. Steps one and two already committed. Nothing rolls back, and nothing notices.

Resource exhaustion

Works perfectly at 10 requests a second. At 400, the connection pool starves and everything downstream degrades.

How Sibyl works

Five steps, every time.

01

Divine

Declare the promises your system can't break — "every charge gets a receipt," "no message is processed twice."

02

Provoke

Sibyl injects real failure conditions at your app's actual boundaries — HTTP, database, queues, the clock itself.

03

Witness

Every run is seeded and deterministic. The exact conditions that caused a failure can always be replayed on demand.

04

Interpret

An agent explains the break in plain language, grounded in the exact events captured — never a guess.

05

Confirm

Ship the fix. The promise becomes a permanent regression test, so the same incident can't happen twice.

The promise DSL

Say what must never break. In code.

import { definePromise } from '@sibyl/sdk'; export const everyChargeGetsAReceipt = definePromise({ name: 'every charge gets a receipt', check: async (ctx) => { const charges = await ctx.query("SELECT id FROM charges WHERE status = 'succeeded'"); const receipts = await ctx.query('SELECT charge_id FROM receipts'); const missing = charges.filter(c => !receipts.some(r => r.charge_id === c.id)); // held: true unless a charge slipped through with no receipt return missing.length === 0 ? { held: true } : { held: false, evidence: { missingChargeIds: missing.map(c => c.id) } }; } });
§

Deterministic, always. Every run carries a seed. Given the same seed and the same fault schedule, Sibyl makes the exact same fault-or-not decision, in the exact same order, every time — so a failure you found once can be replayed on command, not chased again.
